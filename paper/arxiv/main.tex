\begin{abstract}
Static detectors for exception handlers that turn a failed operation into an
ordinary value are often compared with existing linters by counting the
detector findings that no linter reports. That count mixes three things: the
source forms each rule recognises, the files each tool actually analyses, and
the set of findings used as the denominator. We describe a reproducible
measurement protocol that separates them and apply it to an AST-based detector
on eight pinned AI/ML Python packages (2,124 scanned files; 2,270 except
handlers). Sixty-eight generated probes calibrate which selected Ruff, Bandit,
Pylint and flake8 rules fire on which handler and suppression forms. In the
corpus, none of the 19 contextlib.suppress candidates is co-located with a
selected lint warning, or with an exception-related message from all 969 Ruff
rules or Pylint's default set; a project-written Semgrep rule reaches 18. File
discovery matters: Pylint silently skipped 152 files under directories without
\_\_init\_\_.py, and Semgrep 1.175.0 parses one file only partially. Replacing a
name-based coverage mapping with the probe-calibrated one raises the predicted
unmatched share from 18.3\% to 47.1\% with no change in detector output. A
predicate refinement raises measured overlap from 41.1\% to 52.9\% while the
number of co-located findings falls from 255 to 252: the smaller denominator
explains the rise. Both candidate frames, the four-tool coverage rows and the
probe matrix were re-executed from pinned inputs. The study measures warning
coverage only. Exploratory LLM labels and curated maintainer records are
reported with their provenance; they do not establish defect precision or
recall.
\end{abstract}

\noindent\textbf{Keywords:} exception handling; static analysis; warning coverage;
measurement validity; empirical software engineering; machine learning systems.

\section{Introduction}
\label{sec:intro}

An AI evaluator catches an API timeout and returns \texttt{0.0}. A document
loader catches a decoding error and returns an empty string. In both cases the
caller receives a value it could also receive after a successful computation.
We call this conversion of an exception into an ordinary result
\emph{failure-routing}. Whether it is a defect depends on the caller's contract:
a fallback may be intentional, or it may corrupt a score, a security verdict or a
later computation. Swallowed and overly broad exception handling are well-studied
problems~\cite{cabral2007,depadua2017prevalence,souza2026python}, and existing
linters already flag many of their forms.

A new detector for such handlers therefore has to answer a narrower question:
\emph{what does it report that existing tools do not?} The usual answer is a
count of detector findings with no co-located linter warning. This paper argues
that the count is a property of the whole comparison, not of the detector, and
that it moves when any of four inputs moves:
\begin{enumerate}[nosep,leftmargin=*]
\item the source \emph{representation} each rule recognises (an \texttt{except}
  clause and a \texttt{contextlib.suppress} statement can express the same
  suppression);
\item the \emph{files each tool actually analyses}, which need not be the files it
  was pointed at;
\item how \emph{coverage is attributed}: by running the baselines, or by a mapping
  that predicts which rule would fire;
\item the \emph{denominator}: which candidates enter the frame, and whether the unit
  is a finding, a source site or a handler.
\end{enumerate}
Each of these can change the headline share without any change in what the
detector finds or in whether the findings are defects.

We make the dependence explicit through a measurement protocol and apply it to
\texttt{failroute}, an AST-based detector, on eight pinned AI/ML Python packages.
The protocol keeps three kinds of evidence apart (Table~\ref{tab:claims}):
\emph{behavioural calibration} of lint rules on generated probes, which establishes
what a rule fires on; \emph{tool-output coverage} on the corpus, which establishes
which detector findings coincide with a linter warning; and \emph{defect
validity}, which would require independent adjudication of caller contracts. This
paper reports the first two. For the third it reports only exploratory evidence
and states why that evidence does not support precision or recall estimates.

\paragraph{Research questions.}
\begin{enumerate}[label=\textbf{RQ\arabic*},nosep,leftmargin=*]
\item \emph{Representation.} Which selected lint rules fire on the handler and
  suppression forms the detector reports, on generated probes and in the corpus?
  (Section~\ref{sec:rq1})
\item \emph{Read sets and attribution.} How much do the files each tool actually
  analyses, and the way coverage is attributed, change the measured unmatched
  share? (Section~\ref{sec:rq2})
\item \emph{Denominator.} When the candidate predicate changes, how much of the
  change in measured overlap comes from the denominator rather than from the
  number of covered findings? (Section~\ref{sec:rq3})
\end{enumerate}
Section~\ref{sec:validation} then sets out what the available labels and
maintainer records can and cannot add to these coverage results.

\paragraph{Contributions.}
\begin{enumerate}[nosep,leftmargin=*]
\item \textbf{A measurement protocol for detector increments}
  (Section~\ref{sec:protocol}): explicit units (finding, site, handler), a check
  of each tool's read set, probe-based calibration of rule semantics with
  positive controls, paired candidate frames with a denominator decomposition,
  and a rule that partial analyses are reported as bounds.
\item \textbf{Measurements on a pinned corpus}: a representation boundary at
  \texttt{contextlib.suppress} that the tested lint configurations, including
  all 969 Ruff rules and Pylint's default set, do not reach; two file-discovery
  effects; a 28.8-point correction of the predicted unmatched share caused only
  by coverage attribution; and an overlap increase explained by a shrinking
  denominator.
\item \textbf{Executable artefacts with stated audit status}: frozen exports, a
  current reproduction entry point that writes only to new directories, and an
  explicit separation between what was re-executed, what is cited from earlier
  runs, and what could not be re-run (Appendix~\ref{sec:repro}).
\end{enumerate}
We do not claim to be the first to detect exception swallowing or
failure-to-value conversion. Exception Miner already detects handling
anti-patterns in Python with AST queries~\cite{souza2024miner}; Souza et
al.\ analyse 942 manually validated Python exception-handling
bugs~\cite{souza2026python}; and Rollout Cards treats the handling of failed
runs and the choice of reporting rules as a reproducibility problem in agent
evaluation~\cite{masters2026rolloutcards}. Our contribution is the measurement
of a detector's \emph{warning increment} and of the conditions under which that
measurement is valid (Section~\ref{sec:related}).

\section{Related work and positioning}
\label{sec:related}

\paragraph{Exception-handling anti-patterns and bugs.}
Cabral and Marques~\cite{cabral2007}, Sawadpong et al.~\cite{sawadpong2012} and
de P\'adua and Shang~\cite{depadua2017prevalence,depadua2017flow} established
exception handling as an empirical object, including the prevalence of handling
anti-patterns. Exception Miner identifies such anti-patterns in Java, TypeScript
and Python with static AST queries and was evaluated on eleven multi-language
projects~\cite{souza2024miner}. Souza et al.~\cite{souza2026python} analysed 942
manually validated Python exception-handling bugs from 550 projects, including
machine-learning and AI software, and derived root-cause and repair taxonomies
whose categories include swallowing, overly broad handling and incorrect
recovery. These studies characterise the phenomenon more broadly than our
corpus does and, unlike our labels, rest on manual validation. We take the
phenomenon as given and ask a different question: how a detector's incremental
warning coverage over existing linters should be measured, and how sensitive
that measurement is to representation, read sets, attribution and
denominators.

\paragraph{Static-analysis warnings and their evaluation.}
Developers' use of static analysis depends on noise and actionable
feedback~\cite{johnson2013,ruthruff2008,do2022,yedida2023}. Tricorder and the
FindBugs fixit describe filtering and prioritisation in deployed
analysis~\cite{sadowski2015,ayewah2010,sadowski2018}; work on false-positive
mitigation and warning relevance gives further context~\cite{guo2023,querel2018}.
Hu et al.~\cite{hu2025suppressed} study developers' suppression of static
warnings. A warning-suppression annotation and a runtime
\texttt{contextlib.suppress} statement operate at different layers: the latter
changes exceptional control flow. Our probes measure which tested rules reach
that runtime construct. We do not evaluate actionability, and we make no claim
of superiority over other exception-handling tools.

\paragraph{Reporting rules and denominators.}
Rollout Cards~\cite{masters2026rolloutcards} audits agent training and
evaluation repositories and shows that reporting rules, including how failed,
errored or skipped runs are dropped or counted, can change reported scores. It is
the closest prior work in spirit: it already treats failed computations that
enter a score, and the choice of denominator, as reproducibility problems. Our
setting is different, a comparison between static detectors, but the lesson
transfers: a coverage share is only interpretable together with its numerator,
its denominator and the record of what each tool actually analysed.

\paragraph{LLM support and ML-system reliability.}
Souza et al.~\cite{souza2026llm} evaluate prompted LLMs on four Python
exception-handling tasks against a curated benchmark. Here LLM readings are
retained exploratory labels with unrecoverable model provenance; they are not a
benchmark. Pipeline coupling and boundary checks motivate reliability work in
ML software~\cite{sculley2015,polyzotis2019,breck2017,amershi2019,paleyes2022,sambasivan2021};
our corpus is drawn from that domain but our claims are about measurement, not
about ML systems in general.

\section{Measurement protocol}
\label{sec:protocol}

\subsection{Units and the three kinds of claims}
\label{sec:units}

\paragraph{Units.} A \emph{finding} is one output record of the detector. A
\emph{site} is a source coordinate (package, file, line). A \emph{handler} is an
\texttt{except} clause in the AST. These are not interchangeable:
\begin{itemize}[nosep,leftmargin=*]
\item one handler can produce several findings: the assignment channel of
  \texttt{silent-fallback} emits one finding per assigned target, so four sites
  carry two findings in each frame studied here (621 findings on 617 sites; 476 on
  472);
\item a \texttt{contextlib.suppress} statement produces a finding but is not an
  \texttt{except} handler (19 such sites in the 621-finding frame, 16 in the
  476-finding frame).
\end{itemize}
We therefore report ``findings per 100 \texttt{except} handlers'' only as a
ratio of tool output to handler count. It includes suppress findings and repeated
outputs and is \emph{not} the percentage of handlers affected. In the main corpus
(2{,}270 handlers) the refined frame gives 476 findings, or 21.0 per 100 handlers,
while 456 distinct handlers (20.1\%) carry at least one finding; the 621-finding
frame gives 27.4 findings per 100 handlers and 598 handlers with a finding
(26.3\%). Handler counts are from a direct AST count over the scan roots.

\paragraph{Co-location.} A finding is \emph{co-located} with a baseline when that
baseline reports one of its selected rules in the same file within $\pm1$ line,
and \emph{unmatched} when no baseline does. Co-location asks whether a tool
flagged the same place, not whether it expressed the same property: a
broad-except warning can coincide with a failure-routing finding for a different
reason. Coverage results below are co-location counts and nothing stronger.

\subsection{Detector and candidate frames}
\label{sec:detector}

\texttt{failroute} parses each file to an AST and applies the rules of
Table~\ref{tab:shapes} through a shared registry. Five rules concern a caught
failure that is suppressed or routed into a normal-looking value or
continuation; \texttt{name-shadowing} is an adjacent exception-masking hazard.
Rule membership describes a local construct, not a contract violation. Three
gates remove a site before any rule runs: handlers catching only
shutdown, iteration or cancellation exceptions; an opt-out comment; and
per-project configuration. Whether a handler ``records'' the failure is decided
syntactically (re-raise, exit, \texttt{warnings.warn}, or a logger-like call,
with a deliberately stricter test for catch-all handlers). Appendix~\ref{sec:detector-detail}
gives the full predicates and their known asymmetries.

\subsection{Generated probes}
\label{sec:probes}

Coverage can be attributed in two ways: by running the baselines on the corpus,
or by \emph{predicting} from a mapping which rules fire on a handler of a given
form. The v0.9.1 detector ships such a mapping (\texttt{covered\_by}). To make
the mapping an empirical object rather than a reading of rule names,
\texttt{tools/lint\_mapping\_probe.py} generates \textbf{68 probes}: eleven
caught-type forms (bare; \texttt{Exception}; \texttt{BaseException};
\texttt{builtins.Exception}; narrow tuples; tuples mixing \texttt{Exception} with
narrow, dotted or unresolvable members; single and dotted narrow names; a call
expression) crossed with six body forms (\texttt{pass}, \texttt{...},
\texttt{continue}, returned constant, assigned constant, discarded comparison),
plus a broad and a narrow \texttt{contextlib.suppress} statement. All four
baselines run over the probe file, each hit is attributed to the probe whose
function span contains it, and the resulting matrix is written to
\texttt{bench/lint-rule-mapping.json}. Every selected rule has a positive
control, so a selector that silently matches nothing fails the run.
With \texttt{-{}-check-parity} the script also compares the detector's predicted
\texttt{covered\_by} with the measured matrix, probe by probe.

The probes are a \emph{behavioural calibration} of the comparison instrument.
They show what each rule fires on; they say nothing about how often a form occurs
in real code or whether a finding is a defect. They are also distinct from the
detector's 68 unit fixtures (34 positive, 34 negative in fixture set v7), which
test the detector against its own specification.

\section{Results}
\label{sec:results}

\subsection{RQ1: Representation}
\label{sec:rq1}

\paragraph{Probes.} On the generated probes, \texttt{ruff S110/S112} fire on bare
and catch-all handlers (including tuples containing \texttt{Exception} or
\texttt{BaseException}); \texttt{bandit B110/B112} fire only on a bare handler or
exactly \texttt{except Exception:}; and \texttt{S110}/\texttt{B110} fire on a
\texttt{pass} body but not on \texttt{...}. Neither \texttt{contextlib.suppress}
probe, broad or narrow, draws a message from any selected rule. The selected
rule sets are therefore tied to the \texttt{except} representation.

\paragraph{Corpus.} The 621-finding frame contains 19 \texttt{silent-suppress}
findings, in five files of \texttt{inspect\_ai} and
\texttt{pydantic\_ai\_slim}. \textbf{None is co-located with a warning from the
four selected baselines} (Table~\ref{tab:coverage}). Widening the baselines does
not change this: running all 969 Ruff rules and Pylint's full default message set
over those five files yields, within $\pm1$ line of the 19 sites, only line-length
messages (\texttt{E501}, \texttt{C0301}). The project's Semgrep rule co-locates
with 18 of the 19, so the form is expressible by a syntactic rule. In the refined
frame, \texttt{silent-suppress} falls to 16 findings, still with no four-tool

\paragraph{Rule selection.} The selection gives Pylint its broad-except rule
(\texttt{W0718}) but not Ruff's analogue \texttt{BLE001}. Adding \texttt{BLE001}

\subsection{RQ2: Read sets and coverage attribution}
\label{sec:rq2}

\paragraph{A read-set omission in the Pylint baseline.} The original harness
passed each scan root to Pylint as one directory argument. Pylint then skips every
module under a directory without \texttt{\_\_init\_\_.py}, with exit status 0
and no message. In this corpus 152 of the 2{,}124 files (7.2\%) sit under such
directories (\texttt{inspect\_ai} 123, \texttt{deepteam} 20, \texttt{garak} 9).
Passing the file list instead recovers 34 selected messages in 20 of them and
changes nothing on the files already analysed (0 messages lost, 0 gained). The
four-tool union rises from 250 to 255 of 621 and the unmatched count falls from
371 to 366: the omission had \emph{inflated} the detector's apparent increment.
All results in this paper use the file-list invocation. Ruff, Bandit and flake8
return identical hits under both invocations; neither
\texttt{-{}-recursive=y} nor \texttt{-{}-init-hook} recovers the skipped files.

\paragraph{A partial analysis in the supplementary baseline.} Semgrep 1.175.0
reports a syntax error in \texttt{inspect\_ai/model/\_reasoning.py} at line~62, a
\texttt{match} statement, and marks the file as partially analysed; it also skips
one \texttt{deepteam} test module through its default \texttt{.semgrepignore}.
Semgrep exits with status 0 and its console summary reads ``Scan completed
successfully'' (``Parsed lines: \textasciitilde100.0\%''); the error is visible only
in the JSON \texttt{errors} array and in \texttt{-{}-verbose} output. The strict reproduction harness
refuses such a run. A separate diagnostic (\texttt{tools/semgrep\_diagnostic.py})
records the error and bounds its effect: the skipped test module contains no
detector finding, and the partially analysed file contains one finding of the
621-finding frame (line~193, not co-located). The diagnostic observes 274/621
co-located findings with Semgrep added, identical to the historical export, with
an upper bound of 275; for the 476-finding frame it observes 267/476, with no
finding in the affected file. We therefore report the five-tool figures as an
observed value with a bound, not as an error-free reproduction.

\paragraph{Predicted versus executed attribution.} On the 476-finding frame,
executed co-location leaves 224 findings (47.1\%) unmatched. The original
\texttt{covered\_by} mapping, inferred from rule names, predicted only 87
(18.3\%). The probes identified why: the mapping credited \texttt{ruff S110}
and \texttt{bandit B110} to every handler with an inert body regardless of what it
caught, although both are broad-only; it treated \texttt{bandit}'s rules as if
they fired on tuples and on \texttt{BaseException}, which they do not; and it did
not distinguish a \texttt{pass} body from \texttt{...}. In the opposite
direction, a tuple with an unresolvable member, such as
\texttt{except (anyio.get\_cancelled\_exc\_class(), Exception):}, was classified
as narrow and lost the \texttt{W0718} and \texttt{BLE001} credits that do fire on
it. For example, \texttt{garak/analyze/ci\_calculator.py:40} is a literal
\texttt{except (ValueError, TypeError): pass}; the old mapping called it covered,
and all four baselines report nothing on that file.

Correcting the mapping removes credit from 146 findings (all
\texttt{no-action}) and adds it to 3; the predicted unmatched count rises from
87 to 224, a correction of \textbf{28.8 percentage points}. The detector's output
is the same 476 findings before and after, and the executed co-location is the
same 252 covered and 224 unmatched: only the attribution changed. After the
correction, the predicted mapping and executed co-location agree on all 476
findings. Five findings had initially disagreed; all five were in files that the
directory-based Pylint invocation had not analysed, so the residual disagreement
was a read-set effect, not a mapping effect. Thirty-six regression tests pin the
corrected conditions; replaying them against a reconstruction of the
pre-correction mapping (\texttt{tools/refix\_replay.py}) fails 21 of them, so the
tests discriminate between the two versions.

\subsection{RQ3: Candidate predicate and denominator}
\label{sec:rq3}

\paragraph{Frame change.} The v0.9.1 predicate reduces the frame from 621 to 476
findings (617 to 472 sites). The four-tool co-location \emph{rises} from
255/621 $=$ 41.1\% to 252/476 $=$ \textbf{52.9\%}, while the unmatched count
falls from 366 (58.9\%) to 224 (47.1\%). The refinement is not a pruning of the
old frame: over distinct sites, 184 disappeared, 39 appeared and 433 persisted.
Of the 184 dropped sites, 155 (84.2\%) had been unmatched; of the 39 added, 15
(38.5\%) were. The losses concentrate in \texttt{silent-fallback} (177 of 184,
plus 4 \texttt{no-action} and 3 \texttt{silent-suppress}); all additions are
\texttt{silent-fallback}.

\paragraph{Denominator decomposition.} Write the overlap as $O=C/N$, with $C$
co-located findings and $N$ findings in the frame. Then
\[
 O_1-O_0=\underbrace{\frac{C_1-C_0}{N_1}}_{\mbox{\scriptsize covered count}}
          +\underbrace{C_0\left(\frac{1}{N_1}-\frac{1}{N_0}\right)}_{\mbox{\scriptsize denominator}}.
\]
With $(C_0,N_0)=(255,621)$ and $(C_1,N_1)=(252,476)$, the denominator term
contributes $+12.51$ percentage points and the covered-count term $-0.63$, giving
the observed $+11.88$ points. \textbf{Overlap rises although fewer findings are
co-located}; the increase is a property of the smaller frame. The decomposition
describes a ratio change and does not attribute causal effects to individual
predicate heuristics. Whether the smaller frame contains a higher share of
defects is a separate question that the available labels cannot answer
(Section~\ref{sec:validation}).

\paragraph{Instrument versus predicate.} RQ2 and RQ3 change the reported
unmatched share by similar amounts through different mechanisms
(Table~\ref{tab:paired}). The attribution correction leaves all detector outputs
fixed and changes the instrument; the predicate refinement leaves the instrument
fixed and changes the candidates. Reporting either change as ``the detector
improved'' would conceal which mechanism moved the number.

\section{What the coverage results do not show}
\label{sec:validation}

The coverage results establish where selected warnings reach and where they do
not. They do not establish that an unmatched finding is a defect, or that a
detector finds more defects than a simpler one. The project holds three further
kinds of evidence; each is reported with its own denominator and none is pooled.

\subsection{Exploratory LLM labels}
\label{sec:rq2labels}

A stratified random sample of 80 findings (rule $\times$ package strata, seed
20260831) was drawn from an earlier 659-candidate frame and labelled
DEFECT, CONTRACT or FALSE POSITIVE by reading the pinned source. \textbf{Both
labelling rounds were run by LLM agents}, not human raters; they agreed on 80/80
items, which is compatible with shared model bias, and the model identity and
version were not recorded. The labels were 12 DEFECT, 64 CONTRACT and 4 FALSE
POSITIVE. All 12 DEFECT labels are in \texttt{deepteam}, all on bare
\texttt{except:} handlers, and they fall into three copied code families; for
five of them the failure-conversion mechanism is unestablished. A further 60
labels were added purposively, prioritising sites the refinement changed and
sites no linter reaches (1 DEFECT, 58 CONTRACT, 1 FALSE POSITIVE); one rationale
was later found to be incorrect and is recorded in
\texttt{paper/annotation-corrections.json} without relabelling.

These labels served their useful purpose as a debugging instrument: the four
false positives shared one control-flow bug in \texttt{implicit-fallback}, whose
correction removed all ten such findings from the corpus
(Appendix~\ref{sec:corrections}). They \textbf{do not} measure precision: they
are LLM judgements; the refinement was developed against all 140 of them; the
sample no longer represents either current frame (72 of the 80 coordinates
survive into the 621 frame); and the DEFECT labels are clustered in one package.
Among the 104 labelled observations that join the refined frame, 12 of 48
co-located observations and 1 of 56 unmatched observations carry a DEFECT label.
This describes a clustered, partly purposive set and supports no claim about
incremental defect yield. A simple comparator illustrates the point:
\texttt{flake8 -{}-select E722} returns 134 bare-except candidates that include
all 12 original DEFECT-labelled sites, whereas Ruff's \texttt{BLE001} (334
candidates) includes none of them. The full label tables and sensitivity
analyses are in Appendix~\ref{sec:labels}.

\subsection{Curated merged fixes}
\label{sec:rq3fixes}

The historical ledger \texttt{paper/merged-pr-recall.csv} records 16 merged pull
requests, submitted from the author's account, that had been classified as
related to this pattern family. A source-linked audit on 2026-11-03
(\texttt{paper/reference-audit.json}; AI-assisted, not independent human
adjudication) found that these changes do not share a common failure-routing
construct: some are handler-local, some concern non-handler outcomes, and some
are adjacent error-handling changes (for example, one adds a fallback where an
exception previously propagated; another preserves exception identity through
retry wrapping). We therefore \textbf{withdraw} the earlier pooled ratios (3/14
matched, 5/14 handler-reachable, 9/14 non-handler) rather than repair their
denominator by assumption. Individual changes remain useful as concrete examples
of failures outside a handler's local shape, such as a failed judge's NaN entering
an aggregate score (\texttt{cvs-health/uqlm}\#459). Appendix~\ref{sec:maintainer}
summarises these and the broader maintainer records.

\subsection{Control corpus}
\label{sec:control}

The main corpus contains 134 bare \texttt{except:} clauses, 131 in one package,
which hold all 12 original DEFECT labels. To check whether the comparison
depends on that style, the v0.9.1 detector and the same baselines were run on the
style-opposite control corpus (Table~\ref{tab:control}). There, \texttt{flake8

\section{Discussion}
\label{sec:discussion}

\paragraph{Coverage is a property of a comparison.}
The unmatched share depends on the representation each rule recognises, the
files each tool analyses, how coverage is attributed and which candidates form
the denominator. In this study each of them moved the headline figure while the
detector's outputs, or the number of covered findings, stayed fixed or fell: a
read-set omission by five findings, attribution by 28.8 points, and the
denominator by 12.5 points. An unmatched finding is therefore an
observation about one comparison, not evidence of an additional defect.

\paragraph{A protocol for detector increments.}
The study supports five concrete checks for future comparisons of
failure-routing or exception-handling detectors:
\begin{enumerate}[nosep,leftmargin=*]
\item \emph{Lock inputs and verify read sets.} Pin the corpus by hash and record,
  per tool, how many target files were analysed; a silent exit status is not
  evidence of a complete scan.
\item \emph{Calibrate rule semantics with executed probes.} Generate probes for
  every handler and body form the detector reports, including alternative
  representations, give every rule a positive control, and derive any predicted
  mapping from the measured matrix.
\item \emph{Report numerator, denominator and unit.} State findings, sites and
  handlers separately; when the predicate changes, report site identities and
  absolute counts and decompose the ratio change.
\item \emph{Report partial analyses as bounds.} Treat any tool error as an
  incomplete measurement and bound its effect rather than recording it as zero
  coverage or as success.
\item \emph{Adjudicate contracts separately.} Defect precision and recall require
  independent contract adjudication on a sample kept apart from development,
  including findings from simple comparators such as \texttt{E722}.
\end{enumerate}
Checks 1--4 are implemented and executed here. Check 5 is the missing evidence for
any claim of incremental defect detection; a protocol for it is proposed in
\texttt{docs/annotation-revalidation-protocol.md} but has not been executed.

\paragraph{Caller intent is the remaining validation problem.}
A return type may admit \texttt{None} or \texttt{False} without making an
operational failure equivalent to a legitimate value; conversely, a constant
fallback may be intentional. Constructed probes against the v0.9.1 build show
both errors: a typed handler returning \texttt{False} on a database timeout, and
an \texttt{Optional}-returning function returning \texttt{None} on a cache error,
are missed, while a validation loop with a \texttt{return False} handler is
reported at HIGH. Together with the state-flag and call-conversion cases of
Section~\ref{sec:control}, they show that local shape does not determine contract
violation, which is why this paper restricts its claims to warning coverage.

\section{Threats to validity}
\label{sec:threats}

\paragraph{Construct validity.}
Co-location within one line does not establish that two tools diagnose the same
property, and a farther warning may still be relevant. The supplementary Semgrep
rules were written by the author and are reported separately and with a bound.
The probes calibrate rule behaviour on synthetic code; they do not establish the
frequency of each form in practice.

\paragraph{Internal validity.}
The v0.9.1 predicate and its \texttt{covered\_by} mapping were developed on this
corpus and its 140 labels, with no held-out set; the refined-frame results are
descriptive of this development corpus. A harness omission and several
mapping errors were found during the study and corrected
(Appendix~\ref{sec:corrections}); others may remain. The pre-correction mapping
used by the replay is a reconstruction, not a recovered git object.

\paragraph{External validity.}
The main corpus consists of eight purposively selected packages, partly chosen
from the author's contribution history; the control corpus of eight
infrastructure packages represents one opposite style, not a population. All
measurements describe pinned package and tool versions.

\paragraph{Label and record validity.}
All labels were produced by LLM agents whose model identity and version were not
recorded; the label process cannot be reproduced, and the two rounds' agreement
may reflect shared bias. The original annotation protocol does not describe the
process actually run. The curated fixes and closed pull requests were submitted by
the author, their family membership was revised by an AI-assisted audit, and the
tracked-site dataset uses a weaker criterion than the detector. These records are
therefore reported as exploratory and are not combined into any rate.

\section{Conclusion}
\label{sec:conclusion}

Measuring what a failure-routing detector adds over existing linters is a
measurement problem before it is a detection problem. On eight pinned AI/ML
packages, generated probes show that the selected lint rules do not reach the
\texttt{contextlib.suppress} representation, and the corpus confirms that none
of 19 such candidates is co-located with a selected warning. A Pylint read-set
omission, a name-based coverage mapping and a change of denominator each moved
the unmatched share materially, while the detector's outputs, or the number of
covered findings, stayed fixed or fell. The protocol and artefacts make these
effects executable and auditable. Whether the remaining unmatched findings are
defects is a separate question that requires independent contract adjudication
on held-out code, including findings from simple baselines.

\section{Detector details}
\label{sec:detector-detail}

\paragraph{What counts as recording a failure.} A handler is treated as signalling
its failure if it re-raises; calls \texttt{exit} or \texttt{\_exit}; calls
\texttt{warnings.warn} or \texttt{warnings.warn\_explicit}; or calls a
logger-like name. The test is not uniform. A catch-all handler (bare
\texttt{except:} or \texttt{except Exception:}) must call a method named
\texttt{error}, \texttt{warning}, \texttt{warn}, \texttt{exception},
\texttt{critical} or \texttt{fatal}; a typed handler qualifies on \emph{any}
method of a logger-like object, \texttt{debug} and \texttt{info} included. A bare
\texttt{print()} never qualifies. The asymmetry is deliberate (a typed clause
documents an anticipated failure) but does not establish that a debug message
reaches the caller. Only \texttt{silent-fallback} and \texttt{implicit-fallback}
consult the test. ``Logger-like'' is a base-name list (\texttt{logger},
\texttt{logging}, \texttt{log}, \texttt{\_logger}, \texttt{\_log},
\texttt{sentry\_sdk}) plus a suffix heuristic. Handler bodies are traversed
through control flow but not into nested function, lambda or class bodies.

\paragraph{What counts as a fallback value.} A fixed constant set
(\texttt{None}, \texttt{False}, \texttt{0}, \texttt{0.0}, \texttt{""},
\texttt{[]}, \texttt{\{\}}, \texttt{()}), with \texttt{True}, \texttt{1} and
\texttt{1.0} marked ambiguous, plus namespace-qualified sentinels such as
\texttt{Status.UNKNOWN} and configured values. Bare names are never matched.

\paragraph{Exemptions.} Handlers catching only \texttt{KeyboardInterrupt},
\texttt{SystemExit}, \texttt{GeneratorExit}, \texttt{StopIteration},
\texttt{StopAsyncIteration} or \texttt{CancelledError} are exempt (a tuple only
if every member is); so are handlers containing \texttt{\# failroute: ignore} or
\texttt{\# pragma: no cover}, and rules disabled in configuration. The exemption
can hide a genuine mistake.

\paragraph{v0.9.1 refinement.} Three heuristics replace the plain constant test:
(1) \emph{declared value range}: if the enclosing function's declared return type
admits the substituted value, the finding is downgraded (return channel only,
explicit annotations only); (2) \emph{exception--predicate isomorphism}: whether
the handler's work is structurally a \texttt{-> bool} predicate the codebase
declares; (3) \emph{escape channel}: whether the value is returned or assigned to
object state. On the 476-finding frame the isomorphism layer classified no
finding as isomorphic (254 non-isomorphic, 206 unknown, 16 without a handler), so
it contributed nothing to the frame change. Severities: 208 HIGH, 126 MEDIUM, 129
INFO, 13 LOW. Each finding identifier is derived from the handler alone, so the
two findings at a multi-target site share an identifier.

\paragraph{Tests and fixtures.} v0.8.0 has 158 tests and a unit-fixture set (v6)
of 36 positive and 32 negative cases; v0.9.1 has 221 tests and fixture set v7 with
34 positive and 34 negative cases (five narrow-type \texttt{contextlib.suppress}
cases became negative and three other cases changed in the opposite direction).
The current revision has 236 tests. Fixture agreement shows that the detector
implements its specification, not that its findings are defects.

\section{Measurement corrections and revision history}
\label{sec:corrections}

This appendix records corrections made during the study so that earlier figures
remain traceable.

\paragraph{Detector: implicit-fallback control flow (v0.7.0).} All four
false-positive labels in the 80-item sample were \texttt{implicit-fallback}
findings with one root cause: \texttt{\_has\_top\_level\_terminal()} inspected only
direct statements, so a \texttt{return} or \texttt{raise} nested in an exhaustive
\texttt{if/else} was invisible. A recursive analysis covering
\texttt{if/else}, \texttt{with}, \texttt{try/except/finally} and \texttt{match},
with six regression tests derived from the four shapes, reduced the rule's
findings from 10 to 0 and the frame from 659 to 649. The v0.8.0 release removed
28 further findings through four audited fixes (tuple-typed handlers,
\texttt{warnings.warn} as a signal, \texttt{StopAsyncIteration} exemption,
optional-dependency probes): 649 $\to$ 621. No DEFECT-labelled site was removed.

\paragraph{Harness: Pylint read set.} Described in Section~\ref{sec:rq2}. Under
RQ1's narrow selections the 152 affected files yield 5, 0 and 0 messages for Ruff,
Bandit and flake8 under either invocation; under full selections they yield
6{,}879, 104 and 2{,}375 messages, identical both ways. The control corpus has no
\texttt{\_\_init\_\_}-less directory. Without \texttt{click} importable, Pylint
reports 564 rather than 563 messages and the directory invocation hides 35
messages across 21 files rather than 34 across 20; co-location is unaffected.

\paragraph{Harness: Pylint message identifiers.} Pylint accepts the retired
\texttt{W0703} and reports its messages as \texttt{W0718}; over the corpus the
selection emits 423 \texttt{W0718}, 134 \texttt{W0702} and 6 \texttt{W0706}. A
reproducer counting \texttt{W0703} would find zero.

\paragraph{Baseline selection: BLE001.} With \texttt{BLE001} added, Ruff reports
410 findings (76 without) and co-locates with 127 (72 without); the union stays
at 255/621. The Pylint-to-Ruff co-location ratio is therefore 3.54 without
\texttt{BLE001} and 2.01 with it. Ruff 0.16.0, 0.16.4 and 0.16.5 give
set-identical hits for both selections; the committed artefact was produced with
0.16.4 and the paper extra pins 0.16.5.

\paragraph{Mapping: details of the correction.} The 146 findings that lost
credit were all \texttt{no-action} (93 INFO, 48 MEDIUM, 5 HIGH); 137 became
predicted-unmatched and 9 kept a rule that genuinely fires. HIGH findings with no
predicted coverage rose from 20 to 25. \texttt{pydantic\_ai/\_agent\_graph.py:205},
an \texttt{except BaseException: pass}, illustrates why Ruff and Bandit need
separate caught-type conditions. All 146 have a \texttt{pass} body, so the
body-form condition changes no number in this corpus. The pre-correction export
is preserved as \texttt{bench/corpus-coverage-per-finding-v2-pre-coverby-fix.jsonl}.
The five findings that disagreed after the correction were \texttt{except
Exception:} handlers in files under directories without \texttt{\_\_init\_\_.py};
parse failures, inline pragmas and the \texttt{as} binding were tested and ruled
out before the read-set cause was found.

\paragraph{Supplementary baseline: Semgrep audit.} The original paper extra did
not install Semgrep; a pinned \texttt{paper-semgrep} extra was added in the
2026-11-03 audit. The strict harness stops on the parse error described in
Section~\ref{sec:rq2}; \texttt{tools/semgrep\_diagnostic.py} and
\texttt{bench/semgrep-diagnostic-2026-11-03.json} record the bound. The older
\texttt{tools/run\_semgrep\_baseline.py} read the v0.7.0 frame and overwrote
frozen files.

\paragraph{Reference set and labels.} The 2026-11-03 audit withdrew the pooled
reference-set ratios (Section~\ref{sec:rq3fixes}) and corrected one supplementary
rationale: returning \texttt{None} from \texttt{JSONEncoder.default} produces JSON
\texttt{null}, not a not-serialisable signal. The original label is preserved but
not reaffirmed. Earlier versions of this manuscript reported a weighted
projection of 130 LLM DEFECT labels (20.0\%) in the 649-candidate frame; it is a
projection of labels, not of defects, and is not used in the argument.

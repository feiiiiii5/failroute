**Abstract (1,684 ASCII characters, TeX escapes removed; within the 1,920 limit):**

```text
Static detectors for exception handlers that turn a failed operation into an ordinary value are often compared with existing linters by counting the detector findings that no linter reports. That count mixes three things: the source forms each rule recognises, the files each tool actually analyses, and the set of findings used as the denominator. We describe a reproducible measurement protocol that separates them and apply it to an AST-based detector on eight pinned AI/ML Python packages (2,124 scanned files; 2,270 except handlers). Sixty-eight generated probes calibrate which selected Ruff, Bandit, Pylint and flake8 rules fire on which handler and suppression forms. In the corpus, none of the 19 contextlib.suppress candidates is co-located with a selected lint warning, or with an exception-related message from all 969 Ruff rules or Pylint's default set; a project-written Semgrep rule reaches 18. File discovery matters: Pylint silently skipped 152 files under directories without __init__.py, and Semgrep 1.175.0 parses one file only partially. Replacing a name-based coverage mapping with the probe-calibrated one raises the predicted unmatched share from 18.3% to 47.1% with no change in detector output. A predicate refinement raises measured overlap from 41.1% to 52.9% while the number of co-located findings falls from 255 to 252: the smaller denominator explains the rise. Both candidate frames, the four-tool coverage rows and the probe matrix were re-executed from pinned inputs. The study measures warning coverage only. Exploratory LLM labels and curated maintainer records are reported with their provenance; they do not establish defect precision or recall.
```
